# Security and privacy

## Data we collect (only with consent)
- Predicted class, confidence, model version, app version
- The farmer's answer to "Was this correct?" (yes, no or not answered)
- A random install ID generated by the app
- Time of the scan, rounded to the hour on the phone before upload

## Data we never collect
Names, phone numbers, photos, GPS location, device identifiers (IMEI, Android ID, advertising ID), contacts.

## Server
- Every request body is validated (pydantic). Unknown fields are rejected. Class must be one of the 14 labels. Confidence must be between 0 and 1.
- Request bodies above 32 KB are rejected (512 KB for `PUT /advice`). A batch holds at most 50 scans.
- A simple per-IP rate limit protects the free host from floods.
- `GET /stats` returns only aggregate counts.
- CORS is closed by default; the app is not a browser and does not need it.
- Secrets (`DATABASE_URL`, `ADMIN_TOKEN`) come from environment variables only. `.env` is git-ignored.
- `PUT /advice` requires the `ADMIN_TOKEN` bearer token.

## App
- Camera permission is requested only when the user opens the camera screen.
- No analytics SDKs, no ads, no third-party trackers.
- The upload queue is stored locally and sent over HTTPS only.

## Deletion
Because no personal data is stored, a farmer can stop sharing at any time from the settings screen; queued but unsent scans are deleted at that moment.
